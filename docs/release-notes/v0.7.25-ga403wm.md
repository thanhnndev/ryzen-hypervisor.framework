# RyzenHV 0.7.25 (ga403wm)

Source tag `v0.7.25-ga403wm`. Built on 0.7.24 (`11ec930`, PKU fix). One fix, plus the version string.

## Fixed: Android emulator quick boot sometimes restored into a crash (black screen)

**Symptom.** With quick boot, the snapshot saved when the emulator closed sometimes restored into a guest
kernel panic followed by a BIOS reboot, which looks like a black screen. Cold Boot always worked. It looked
random because it depended on where the virtual CPU was at the moment of the save: snapshots taken while the
guest was idle in its kernel restored fine; snapshots taken while it was running app code (user mode) failed.

**Cause.** AMD SVM keeps the guest's current privilege level (CPL) in its own VMCB field. Intel VMX, whose API
RyzenHV implements, has no such field: the CPL is the DPL of the stack segment (SS). RyzenHV translated SS
writes into the VMCB segment but never updated the VMCB CPL, which stayed at 0 from reset. Reading SS back had
the matching gap: on AMD, `SYSRET` leaves the saved SS.DPL at 0 while the CPU runs at CPL 3, so a snapshot saved
in user mode recorded a user code segment (CS DPL 3) with a kernel-level SS (DPL 0). On restore the guest
resumed user code at CPL 0; the first interrupt was then delivered without a privilege change, on the user
stack with the user GS, and the kernel faulted recursively (`exc_page_fault`, `current_task` = 0), hit the
IRQ stack guard page and panicked.

**Fix** (`kext/Source/VmcsState.hpp`), the same rule KVM uses (`svm_set_segment` / `svm_get_segment`):

- a write of `GUEST_SS_AR` (VMCS 0x4818) sets VMCB CPL to the written DPL;
- a read of `GUEST_SS_AR` reports VMCB CPL as the DPL.

Clients that write SS at privilege 0 (HyperKit/Docker on reset and state loads) are unchanged. CPL is covered by
the existing segment clean bit, so the VMCB cache from 0.7.22 sees the change. The host test
`tests/vmcs_state_test.cpp` covers both directions, the `SYSRET` case and an unusable SS.

**After updating:** a quick-boot snapshot saved by 0.7.24 or older while the guest was in user mode keeps the
wrong SS and still fails. Use **Cold Boot** once; snapshots saved from then on restore correctly.

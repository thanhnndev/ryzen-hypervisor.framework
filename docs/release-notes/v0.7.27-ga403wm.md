# RyzenHV 0.7.27 (GA403WM): exit mix by class

On top of 0.7.26 (queue/after-0.7.25). Measurement only: no change to how any exit is handled.

## What it adds
- Stats V6, 79 words. V5 (0.7.23-0.7.26) and older layouts are still accepted, and the new `rhv-info` still reads an older kext.
- `vmExitAll[16]`: every #VMEXIT by class. This includes the ones the kernel handles itself: host interrupts, lazy-RAM first touches,
  the TSC write, CR8, CLTS/LMSW.
- `vmExitOut[16]`: the exits handed to the client (HyperKit, QEMU), by the same class. Each one ends a VmRun. The extra class
  `Timeslice` counts returns for the deadline, a kick or a synthetic reason.
- `vmApicNpf[4]`: client NPF exits on the xAPIC page (GPA 0xFEE00000), split into EOI, ICR, TMICT and other.
- The classes come from the SVM exit code (`kext/Source/ExitClass.hpp`, tested by `tests/exit_class_test.cpp`): Intr, Nmi, Vintr,
  Cr, Dr, Excp, Cpuid, Hlt, Io, Rdmsr, Wrmsr, Npf, Pause, SvmInsn, Other, Timeslice.
- Cost: one per-vCPU increment per exit, plus one more on the way out. They are added to the global counters in the existing
  1024-exit batches.
- A vCPU now flushes its last partial batch when it is freed. Before, up to 1023 exits of profiling per vCPU were lost at VM exit.
- `rhv-info stats` prints one `  name : value` line per counter (`exitAllHlt`, `exitOutNpf`, `apicNpfEoi`, ...), so
  `ga403wm-power/scripts/docker-heat-probe.sh` picks them up as columns.

## Install
- Same as any RyzenHV update: kext plus the new `build/rhv-info`.
- No boot-arg, and nothing to switch.

## 3. The Android emulator stall: root cause and fix

**Symptom.** The Android Studio emulator showed a black screen. The guest kernel reached about 13.9 s
("dlkm_loader: module load count is 47"), then silence; adb stayed offline; qemu sat near 100 % CPU.

**Root cause.** The client (QEMU with `-accel hvf`) builds the guest's CPUID from the host. CPUID leaf 7 passed PKU and
OSPKE through (Zen 5 has protection keys). macOS never enables PKRU state in XCR0, so leaf 0xD, cut down to the host
thread's XCR0, offers no PKRU state component. A Linux 6.12 guest (Android 37) then sets CR4.PKE but cannot build a
signal frame: `get_xsave_addr_user(PKRU)` returns NULL, the write of PKRU into the frame faults, and the signal is
retried for ever. `init` never gets past its first signal.

**Fix (`11ec930`).** The front end cleans every client's CPUID answer: leaf 7.0 ECX PKU and OSPKE, and leaf 0xD.0 EAX
bit 9 (the PKRU state component). RyzenHV could not give a guest PKRU anyway: a guest XCR0 may only hold state the host
thread enabled. This is the same fix as upstream 0.7.9's `62fcd1d` (pull request 11 by suwardhana, "Hide PKU/OSPKE from
the guest's CPUID leaf 7 for every client"), written independently against the fork's tree, plus the leaf 0xD bit.
It takes effect for VMs started after the kext loads.

**Verified on the machine, 2026-11-25:** after a cold boot ("Cold Boot Now") the owner's AVD boots. The release text
published the same day records Android 37 reaching `sys.boot_completed` in 24 to 32 s on a cold boot, with the guest no
longer listing `pku`.

**One thing to do once.** A quick-boot snapshot is also saved by a stalled guest, and restoring it restores the stall.
Discard it once: start the AVD with "Cold Boot Now". This is also why "it worked under 0.7.21" in earlier notes was
never true: a snapshot from a stalled guest looked like a boot.

Not the cause: the VMCB clean bits and kept ASIDs of 0.7.22 (`hv cache`), lazy guest RAM (0.7.23), host graphics.

## 5. Run-time switches (`build/rhv-info`, from `make tools`)

| Command | What it does | Default |
|---|---|---|
| `rhv-info hv cache N` | Which of the 0.7.22 VMRUN shortcuts are used. Bit 0: VMCB clean bits. Bit 1: keep the ASID. `0` = every VMRUN as in 0.7.21. Any change makes every vCPU start clean once. Admin to set | `3` (0.7.23 behaviour) |
| `rhv-info hv exctrace MASK` | Debug only: records guest exceptions (#UD #NM #TS #NP #SS #GP #PF #AC by bit) the client does not intercept itself, into a 1024-entry ring: vector, error code, rip, rsp, rflags, #PF address, control registers, the first 16 code bytes. Admin to set | `0` (off) |
| `rhv-info hv excdump N` | Logs the last N entries of that ring | n/a |
| `rhv-info hv reclaim 1` | 0.7.23 step 2: unwire cold lazy guest RAM. Root. Resets to off at every boot | off |
| boot-arg `rhv_lazymap=0` | Back to wiring a whole guest map at once | lazy on |

The release text published on 2026-11-25 records that an A/B of all four `hv cache` settings made no difference to the
emulator stall.

## 6. Known issues

- **Quick boot of the emulator.** The published release text records: restoring a snapshot saved from a healthy guest
  works, but a snapshot written when the emulator closes is sometimes unusable (2 of 3 "cold boot, then close" cycles).
  Under investigation. If the screen stays black after a quick boot, use "Cold Boot Now" again.
- **Orphaned HyperKit after quitting Docker Desktop 4.98**: it spins two cores when it later gets SIGTERM. Reproduced
  2026-11-23 and traced to a HyperKit deadlock (`vmn_read` parks holding the rx mutex). RyzenHV is not involved.
- **CLTS / LMSW are decoded as MOV to CR0** and reach the client that way. Pre-existing. The fix is written on the branch
  (`00bffe5`, test `bfc81f0`) and is **not** in this tag: it has not been loaded.
- **Upstream 0.7.9's read-only map fallback is not ported** ("read-only mappings are pinned for reading").
- The EXIT_INTR path re-injects soft events the way the lazy path no longer does (follow-up noted in `cd6f384`).
- The kext log line says 0.7.22 (section 1).
- HyperKit's xAPIC emulation is the main remaining CPU cost; idle Docker on 8 vCPUs costs about 0.18 of a core.
- Sleep with a running VM: not retested on this machine.
- **Not tested in the fork at all:** Parallels, VirtualBox, VMware Fusion, the RyzenHV app, upstream's QEMU bundle, and
  macOS 15. Upstream's "What works" table in `README.md` describes upstream's machine, not this fork.
- `-FIOff` is required on this machine: ForgedInvariant's per-core TSC writes caused `fq_codel` panics.
- Never install an incremental build (the 0.7.18 lesson). Use `make kext-release`.
